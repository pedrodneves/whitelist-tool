Claude responded: The backend (app.

The backend (app.py) is deployed on Render as a web service, configured entirely through Render's UI — no separate repo for it. The setup is:

  • Render Web Service pointing at the pedrodneves/whitelist-tool GitHub repo
  • Render auto-detects Python, runs gunicorn app:app (from requirements.txt which includes gunicorn)
  • Environment variables (GITHUB_PAT, GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET, FRONTEND_URL, etc.) are set manually in Render's dashboard under Environment
  • No Render-specific config files (render.yaml) were created — it's all through the UI

The frontend (index.html) is a separate static file served via GitHub Pages from the pedrodneves/whitelist-tool repo — nothing to do with Render's static site hosting.

So to answer the question directly: no low-code/no-code builder was used — it's a standard Render web service deployment pointing at a GitHub repo, configured through Render's dashboard UI. The only "Render-specific" thing is that gunicorn is in requirements.txt so Render knows how to start it.
